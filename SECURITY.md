# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability affecting Tag Party, please report it
privately rather than opening a public GitHub issue.

Security vulnerabilities may include, for example:

- unintended access to sensitive data or credentials;
- command or code execution vulnerabilities;
- unsafe handling of external input;
- vulnerabilities in repository tooling, build scripts, or CI workflows;
- exploits that could materially affect the integrity or security of a Tag Party
  installation or development environment.

Gameplay bugs, balance issues, map exploits, and ordinary in-game glitches should
normally be reported through the public issue tracker instead.

Until a dedicated security contact is published, please contact a project
maintainer through an available private project communication channel.

When reporting a vulnerability, include where practical:

- a description of the issue;
- steps to reproduce it;
- the affected component or version;
- potential impact;
- any relevant logs, screenshots, or proof-of-concept information.

Please avoid publicly disclosing a vulnerability before the project has had a
reasonable opportunity to investigate it.

## Scope

This policy applies to code, tooling, automation, and other material maintained
by the Tag Party project.

Vulnerabilities in Dota 2, Source 2, Steam, or other Valve software should be
reported to Valve through its appropriate security reporting channels.

Third-party dependencies remain subject to their respective maintainers and
security processes.

## Supported Versions

Tag Party is currently under active development.

Security fixes are generally applied to the current development version rather
than maintained across multiple historical releases.

This policy may be updated when Tag Party begins publishing stable versioned
releases.
